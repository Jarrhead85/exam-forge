# Exam Forge

Учебный портал для проведения тестов и контрольных: преподаватель готовит банк заданий, собирает версии тестов, назначает работы и проверяет результаты; студенты проходят работы онлайн по одноразовому коду, общей ссылке или личному аккаунту.

## Возможности

- **Банк заданий**: девять типов вопросов (выбор ответа, короткий/развёрнутый ответ, сопоставление, сборка букв, порядок, пропуски, структура), черновик → публикация, правки создают новые редакции без изменения уже собранных версий тестов.
- **Конструктор тестов**: версии из опубликованных заданий, blueprint-предпросмотр, варианты с перемешиванием по seed, печать листов студента и ключей (A4).
- **Назначения**: контрольная или тренировка по расписанию, лимиты времени, выдача кодов по одному или группе. Студенты входят по коду, общей ссылке или через аккаунт.
- **Проведение**: сервер владеет таймерами и состояниями попытки (FSM), автосохранение ответов с ревизиями, корректная обработка обрыва связи и дедлайнов.
- **Проверка и результаты**: очередь с фильтрами, ручная оценка и история переоценки, единая ведомость на экране и в CSV/XLSX, разбор по заданиям и темам, бумажные работы со сканами.
- **Справочники**: словари с импортом из PDF, группы с импортом состава из CSV, предметы и лекционные материалы.
- **Пробное прохождение**: преподаватель проверяет свою работу глазами студента. На /demo и /demo/teacher доступны примеры с вымышленными данными.

## Технологии

- .NET 10, ASP.NET Core Blazor Web App: кабинет — Interactive Server, вход студента — серверная форма, прохождение — WebAssembly.
- PostgreSQL 17 + EF Core (миграции применяются вручную, без автозапуска)
- Модульный монолит: Domain → Application → Infrastructure → Web (Domain не зависит от UI/EF)
- PdfPig (импорт словарей), ClosedXML (экспорт ведомости), ASP.NET Core Identity
- Без внешних CDN и аналитики; CSP без inline-скриптов; все статические ассеты локальные

## Структура

```
src/
  ExamForge.Domain/          # доменная модель и правила (чистая логика)
  ExamForge.Application/     # сценарии, DTO
  ExamForge.Infrastructure/  # EF Core, Identity, файлы, сервисы
  ExamForge.Web/             # хост: кабинет преподавателя, API, печать
  ExamForge.Web.Client/      # студенческий WASM-клиент
tests/
  ExamForge.UnitTests/       # домен и логика
  ExamForge.IntegrationTests# API и поток студента на TestServer
docs/UI_KIT.md               # дизайн-система (токены, компоненты)
design/                      # токены и HTML-референс оформления
deploy/docker/               # Dockerfile, docker-compose, env.example, deploy.sh
```

## Быстрый старт

Требуется .NET 10 SDK и PostgreSQL.

```bash
dotnet restore ExamForge.sln
dotnet ef database update --project src/ExamForge.Infrastructure
dotnet run --project src/ExamForge.Web --launch-profile https -- --seed-admin <login> <password> "<ФИО>"
dotnet run --project src/ExamForge.Web --launch-profile https
```

Приложение поднимется на `https://localhost:7039`. Строка подключения задаётся в `src/ExamForge.Web/appsettings.json` или переменными окружения.

## Docker

В `deploy/docker` скопируйте `env.example` в `.env` и укажите пароль БД, HMAC-ключ и домен.
Трафик проходит через HTTPS-прокси. Пример конфигурации находится в `deploy/nginx`.

```bash
cd deploy/docker
cp env.example .env
# Заполните .env и настройте HTTPS-прокси.
bash deploy.sh
docker compose run --rm app --seed-admin <login> <password> "<ФИО>"
```

Скрипт сохраняет резервные копии, применяет миграции и проверяет `/health/ready`.
Резервные копии содержат учебные данные. Храните их с ограниченным доступом и проверяйте восстановление на отдельной БД перед обновлением пилота.

Перед обновлением сохраните тег или ID образа запущенного контейнера и действующие настройки, включая HMAC-ключ. При откате восстановите `database.dump` в новую базу, `storage.tar.gz` в пустой том файлов и запустите предыдущий образ с восстановленными ресурсами и прежним томом Data Protection. Перед переключением прокси проверьте вход и доступность данных на предыдущей версии. Записи, сделанные после резервного копирования, останутся в обновлённой базе.

В PR на `main` GitHub Actions запускает [проверку обновления](.github/workflows/docker-upgrade.yml). Она собирает обе версии, применяет миграции к синтетическим данным предыдущей версии, запускает Playwright через HTTPS и проверяет восстановление базы, файлов и запуск предыдущего образа.

## Тесты

Для интеграционных тестов нужен PostgreSQL и пользователь с правом создавать базы.
Задайте адрес отдельного тестового сервера через `EXAMFORGE_TEST_DB`.
Набор создаёт уникальную временную БД, применяет миграции и удаляет только созданную им БД.

```bash
dotnet test ExamForge.sln -c Release
```

Playwright проверяет вход, сдачу и восстановление связи, кабинет, массовый старт группы и пробное прохождение. См. [инструкцию E2E](e2e/README.md).

## Безопасность

- Секреты только через переменные окружения (`env.example` — шаблон без значений).
- В базе хранятся хеши паролей и HMAC кодов. Приглашение показывает код при выдаче или перевыпуске.
- Антифорджери на всех изменяющих запросах, CSP `script-src 'self'`, заголовки nosniff/X-Frame-Options/Referrer-Policy.
- Файлы студентов хранятся на диске с проверкой сигнатуры PDF и лимитом размера.
